## What this is
macOS menu-bar **clipboard history manager**. Watches the system clipboard, stores text + image history to disk, and a **⌘⇧V** floating panel (fuzzy search · list · detail) finds and pastes past clips. Phase 2 adds an **actions** layer: per-item pipelines of typed steps (`script` / `ai`) that transform the text and paste the result, plus **⌃⇧V** to transform the current selection in place.

Successor to **AI Replace** (`../ai-replace`). Bundle ID `io.github.macrosak.recallyx`. Built in commit-sized slices.

> **`docs.local/`** (gitignored) holds implementation plans, design docs, and design references for your own use. **Never reference it anywhere that gets committed or published** — not in commit messages, PR descriptions, README, or any tracked `.md` file. This note is the only place it's named.

- **⌘⇧V** → history panel: search clipboard, ↵ pastes the selected clip, ⇥ opens its action menu.
- **⌃⇧V** (Phase 2) → grab the current selection, push to history, open the panel on its action menu (the AI-Replace replacement).

## Build
- **`./scripts/install-dev.sh` — the owner's daily path + the only sync-capable build.** Team-signed Release build via Xcode CLI: `xcodegen generate` → `env DEVELOPER_DIR=<Xcode> xcodebuild -project Recallyx.xcodeproj -scheme Recallyx -configuration Release -derivedDataPath .build/xcode -allowProvisioningUpdates build` → replaces `~/Applications/Recallyx.app` + relaunches. Auto-detects full Xcode (honors `DEVELOPER_DIR`, else `/Applications/Xcode.app`, else `mdfind`); friendly-fails if xcodegen / `Local.xcconfig` / full Xcode is missing. **`--build-only`** builds but skips killall/copy/open — **the only variant agents run** (the owner's app is usually running; never run the full install path or killall Recallyx). Only this build carries the CloudKit entitlement + real team signing, so **iCloud sync runs only here** (the ad-hoc `bundle.sh` build lacks the entitlement, so mirroring is **guarded off** — see `processHasCloudKitEntitlement`; enabling the toggle there is on-but-inactive, not a crash). Needs full Xcode + `brew install xcodegen` + a gitignored `Local.xcconfig` with `DEVELOPMENT_TEAM` (**never commit a team id**). `project.yml` now emits a **shared scheme** for the app target (`schemes:` block) — without it `-scheme Recallyx` collides with the `RecallyxCore` package's own `Recallyx` *executable* target and `xcodebuild` builds the bare SPM binary instead of the signed `.app`.
- `./scripts/testflight.sh` — archive + upload the iOS app (scheme `RecallyxiOS`) to TestFlight. Preflight (xcodegen / full Xcode via `install-dev.sh`'s finder / `DEVELOPMENT_TEAM` extracted with an **anchored** grep `^[[:space:]]*DEVELOPMENT_TEAM[[:space:]]*=` — a naive grep matches the example's comment line). **Stamps `CFBundleVersion`** in `Sources/RecallyxiOS/Resources/Info.plist` with `git rev-list HEAD --first-parent --count` (App Store Connect rejects a duplicate build number; `RECALLYX_BUILD_NUMBER` overrides) and **trap-restores** the plist byte-for-byte afterward, then `xcodegen generate` → `xcodebuild archive` (`-destination generic/platform=iOS`, `-allowProvisioningUpdates`) → `-exportArchive` with a generated `.build/ExportOptions.plist` (`app-store-connect`/`upload`/`signingStyle automatic`, teamID from Local.xcconfig). **`--archive-only`** stops after the archive (verify without spamming TestFlight). Catches the `Failed to Use Accounts` export failure → "sign into Xcode → Settings → Accounts, restart Xcode once, re-run". Needs the paid team + an Apple ID signed into Xcode.
- README documents the team-signed Xcode build as the **primary** build (required for iCloud sync); the ad-hoc `bundle.sh`/`install.sh`/DMG path is the zero-cost alternative (CLT-only, no Apple account, ad-hoc signed → **no iCloud entitlement, so sync is guarded off**; the toggle there is disabled + captioned) and what CI releases.
- **CloudKit environment = Production for all builds.** Both entitlements files set `com.apple.developer.icloud-container-environment` = `Production` (string). Development-signed builds (`install-dev.sh`) otherwise default to the CloudKit **Development** environment while TestFlight/App Store builds **always** use **Production** — so without this key the owner's dev-signed Mac app could never sync with the TestFlight iPhone app. The key is honored for dev-signed builds and ignored/forced-to-Production for App Store exports, so it's safe everywhere (and inert on the ad-hoc build, which never applies the iCloud entitlements). **Prerequisite:** the container schema must be **deployed to Production once** before the first sync (CloudKit Console → the container → Deploy Schema Changes to Production). **Migration caveat (to verify on device):** `NSPersistentCloudKitContainer` tracks per-record export state in persistent history; records already exported to the **Development** environment may be treated as already-exported and **not** backfilled into the (empty) **Production** database after the switch. A record only re-exports when it gets a fresh persistent-history transaction — the practical nudge is to rewrite a field on every row (e.g. touch a UUID/timestamp attribute and save) or start from a fresh store. Not built here; confirm behavior on-device. **Schema-evolution runbook:** because every build targets Production and Production never auto-evolves its schema, adding/renaming a `ClipEntity` attribute breaks Production exports (`CKError.partialFailure`, now shown readably — see `SyncActivityMonitor` below) until: `./scripts/install-dev.sh --ck-dev` (builds against Development, trap-restoring the entitlements after) → copy something once to create the field in the Development schema → CloudKit Console → **Deploy Schema Changes to Production** → rebuild WITHOUT `--ck-dev`.

Honors `RECALLYX_VERSION` (set by CI) — stamps `CFBundleShortVersionString`/`CFBundleVersion`, stripping any `-suffix` to keep the plist numeric. **The release path — unchanged; ad-hoc, so it lacks the iCloud entitlement and its CloudKit mirroring is guarded off (`processHasCloudKitEntitlement`).**
- `./scripts/make-dmg.sh` → `Recallyx-<version>-arm64.dmg` (built-in `hdiutil`, drag-to-install layout). Needs `Recallyx.app` built first; honors `RECALLYX_VERSION` for the filename.

The `List` has **`.refreshable`** (pull down): `store.isCloudSyncActive` short-circuits an instant no-op when sync is off/unentitled; otherwise `sync.awaitNextImport(timeout: 4s)` parks the waiter and — from its `onParked`, so the kick happens *after* parking (a fast import can't signal into an empty waiter) — calls `store.refreshFromCloud()` to reload → import, holds the native spinner, then `store.refreshItemsFromStore()` surfaces the downloaded rows. See the sync-refresh note below for what it guarantees. `SettingsView` = a sheet with the **iCloud sync** toggle via `@AppStorage("iCloudSyncEnabled")` (default on; read once at launch → relaunch-to-apply, same contract as mac) plus, when sync is on, a **Last sync** `LabeledContent` line from `SyncStatusLine.text` (observing the shared `SyncActivityMonitor` passed as `sync.activity`; "Waiting…" until the first event). Fine on a team-signed device build. - **iOS Share Extension (`Sources/RecallyxShareExtension/` + `ShareClipWriter` in RecallyxCore).** "Share to Recallyx" from any iPhone app's share sheet → the shared **text** (or a web URL's string) is saved into the clipboard history and syncs to the fleet. **Target** (`project.yml`): `app-extension`, bundle id `io.github.macrosak.recallyx.share` (must be prefixed by the app id), embedded in `RecallyxiOS` via a `- target: RecallyxShareExtension` dependency (Xcode auto-adds the "Embed App Extensions" phase → `Recallyx.app/PlugIns/RecallyxShareExtension.appex`). `Resources/Info.plist` sets `NSExtensionPointIdentifier = com.apple.share-services` (the value that surfaces it in the share sheet) + a principal-class `$(PRODUCT_MODULE_NAME).ShareViewController` + activation rule (`NSExtensionActivationSupportsText` + one web URL). `Resources/RecallyxShareExtension.entitlements` = **App Group ONLY, deliberately NO CloudKit** (public ids, no team id). **`ShareViewController`** is a lean plain `UIViewController` (not `SLComposeServiceViewController`): reads the first text/URL item provider, `CapturedClip.forText(sourceAppName: "Share Sheet", sourceDeviceName: UIDevice.current.name, sourceDeviceType: "iphone")`, saves via `ShareClipWriter`, flashes a checkmark card (~0.7s), completes. **`ShareClipWriter`** (RecallyxCore, NOT `HistoryStore` — that's `@MainActor` + loads the whole history, too heavy for an extension's ~120 MB ceiling): opens the app-group store `PersistenceController(cloudSyncEnabled: false)` (plain **local**), does one `contentHash` fetch, then inserts or **dedupe-bumps** exactly one `ClipEntity` on a background context (mirrors `HistoryStore.add`'s insert / bump semantics: bump keeps `createdAt`, refreshes `lastUsedAt`+`recency`). `appGroupBaseURL()` resolves the shared container. **Why local-only still syncs (the load-bearing reasoning):** loading a CloudKit-mirrored store from a secondary/short-lived process is the documented crash/conflict zone, so the extension never enables CloudKit. But `PersistenceController.makeStoreDescription` sets `NSPersistentHistoryTrackingKey` + `NSPersistentStoreRemoteChangeNotificationPostOptionKey` on **every** store — so the extension's insert is a persistent-history transaction on the shared SQLite file. The **main app** (running, entitled, mirrored) owns the mirror: `NSPersistentCloudKitContainer` exports local changes by processing that shared history regardless of which process wrote them → the clip uploads to CloudKit → reaches the Macs. The app's `HistoryStore` also observes `.NSPersistentStoreRemoteChange` for the sibling-process write → `mergeRemoteChanges` surfaces it live. If the app **isn't running** when the share happens, nothing is lost — the transaction is exported at the app's next launch when its container processes history. **`ShareClipWriter` is unit-tested** (`ShareClipWriterTests`): write via the writer, read back via a `HistoryStore` on the same temp store (the sibling round-trip), asserting insert/bump/distinct-rows/cross-instance dedupe. **Attended-verify only** (needs a team-signed device build + the iCloud account + 2 devices): the real end-to-end share → app-group write → CloudKit export → Mac. An **unsigned simulator** build resolves no app-group container (`containerURL` → nil), so a sim share reports "Couldn't save" — device-only.

## CI / Releases (`.github/workflows/`)
- `pr-checks.yml` — runs `swift test` on PRs to `main` (macos-26 — gives the macOS 26 SDK with FoundationModels for the on-device AppleClient path).
- `release.yml` — on push to `main`: derive version `0.<N>` (`N = git rev-list HEAD --first-parent --count`, like AI-Replace's eywa scheme but `0.N` not `vN`), `swift test` gate → `bundle.sh` (ad-hoc) → `make-dmg.sh` → `gh release create` with the DMG. **No version-bump commit; the count is the version.** A `gh release view` guard makes re-runs idempotent.
- **Manual `workflow_dispatch`** (any branch via the native ref picker) → **pre-release** tagged `0.<N>-<branch-slug>.<short-sha>`, marked `--prerelease` so it never becomes "Latest".
- Signing is **ad-hoc** (no Apple secrets); notarization is a future drop-in gated on secrets (the seam lives in `bundle.sh`). Repo is public → `macos-26` runners are free.

## Source layout
The package splits into two targets: **`Sources/RecallyxCore/`** is a library of the portable, platform-free logic (Foundation/CryptoKit/FoundationModels/Vision/Security/os only — the iOS-reusable *brain*): AIProvider, Action, ActionMenuItem (the pure `BuiltinAction`/`ActionMenuItem` models, extracted from the SwiftUI ActionMenu), ActionRunner, the AI clients (Anthropic/Apple/Gemini/OpenAI+ModelCatalog/Ollama), AppState, ClipOrigin (the origin-device badge helper), SyncActivityMonitor + SyncStatusLine (the shared CloudKit sync-status core), FuzzyMatcher, HistoryItem, HistoryStore (+ ClipModel / PersistenceController — the programmatic Core Data stack), HistoryPanelViewModel (+ ClipTime), IconCatalog, KeychainStore, Log, OCRService + VisionTextRecognizer (Apple Vision OCR for image search), ScriptRunner, PrivacyFilter (string-UTI based — AppKit-free), AppIconResolving (the icon-resolver protocol; AppKit impl stays in the app). Its public types are `public` only where the app/tests reference them. **`Sources/Recallyx/`** is the `Recallyx` executable (the macOS app) — all AppKit/SwiftUI/Carbon/AX/menu-bar/panel/paste code, plus `Settings.swift` and `Shortcut.swift` (Shortcut is Carbon/AppKit so Settings stays with it) and `AppIconProvider` (the `NSWorkspace`-backed `AppIconResolving` impl — AppKit glue stays here). App files `import RecallyxCore`. Tests `@testable import` both. (Future: an iOS app reuses RecallyxCore.)
- `RecallyxApp.swift` — `@main` + `NSApplicationDelegate`. **All launch wiring lives in `applicationDidFinishLaunching`** (see Lessons — MenuBarExtra content is lazy).
- `AppState.swift` — `@MainActor ObservableObject` (status / lastError / historyCount).
- `StatusItemView.swift` — menu-bar dropdown. Includes **Search history** and **Transform selection** items whose key equivalents are derived live from the saved `Shortcut`s (observes `SettingsStore`; disabled hotkey → no key hint, item stays). The equivalents only fire while the menu is open, so they mirror — not double-trigger — the global Carbon hotkeys. When sync is running (`syncActive` = `store.isCloudSyncActive`) it shows one compact **`SyncStatusLine.text`** line (`Last sync: ↑…· ↓…` / `Sync error: …`) under the clip count, observing the shared `SyncActivityMonitor` (built in the App body, passed from the delegate).
- `MenuBarIconImage.swift` — the menu-bar glyph: the brand mark (stacked clips, same viewBox-24 geometry as `BrandMark`) rendered as a resolution-independent **template** `NSImage` so macOS tints it for light/dark bars. `MenuBarIcon` (in `RecallyxApp.swift`) shows it at idle and swaps in an SF Symbol for working/success/error feedback.
- `Log.swift` — `os.Logger` (subsystem `io.github.macrosak.recallyx`) mirrored to stderr **and** to the persistent `FileLog`.
- `FileLog.swift` (RecallyxCore) — **on-by-default, local-only, content-free** rotating file sink. macOS doesn't persist info-level os_log to disk, so this is what's available when a user reports a bug. Mirrors every `Log.*` line to `~/Library/Logs/Recallyx/recallyx.log` (honors `RECALLYX_DATA_DIR` → scratch dir for debug runs), timestamp-prefixed, **off the main thread** via a private serialized writer actor (`FileLogWriter`). **2-file rotation:** over `maxBytes` (2 MB) → rename `recallyx.log` → `recallyx.log.1` (replacing any prior `.1`), start fresh; footprint bounded at ~4 MB. Injectable file URL + `now` clock seam (mirrors `UsageJournal`); `lastWrite` lets tests await the off-main append. `clear()` deletes both files (awaits the in-flight write first). **Privacy contract = the usage journal's:** the sink writes exactly the (length/category/count) strings `Log` is given and adds none of its own — call sites must never pass clip text / image bytes / clip file paths. `AppDelegate.runAction`'s catch logs the error *category*, never `error.localizedDescription` (a failing script step carries its stderr, an AI client its response body — both can echo clip text; `state.lastError` + the notification, both transient/non-persisted, keep the readable detail). `FileLog.shared` is the production sink, gated by `AppSettings.fileLogEnabled` (default **true**, threaded in at launch + via `settingsStore.onChange`). Settings General → **Diagnostic log (local only)** toggle + Reveal-in-Finder/Clear, beside the usage-journal controls. Unit-tested.
- `UsageJournal.swift` — `@MainActor final class`. **Opt-in, off-by-default, local-only** usage record: append-only JSON Lines to `~/Library/Application Support/Recallyx/usage.jsonl` (honors `RECALLYX_DATA_DIR`). `log(event, fields)` **no-ops immediately when disabled** (first check), else serializes one sorted-keys JSON line and appends **off the main thread** (`Task.detached`, tracked in `lastWrite` so tests await it). **Hard privacy rules:** no network code of any kind; never logs clip text / image bytes / clip file paths; search logs `queryLength: Int` only (never the text); errors log a category *string* (from the error type), never the raw message. **Size cap:** 2 MB; on an over-cap append it truncates-from-front (drops oldest lines) down to ~1.5 MB, keeping newest. Injectable file URL + `now` clock seam for hermetic tests. `clear()` deletes the file. Events: `panel_open{mode}`, `search{queryLength,resultCount}`, `paste{via,clipKind,queryLength?,rank?,resultCount?}` (the rank fields are present only when a search query is active — the pasted clip's 1-based position in the filtered results, for a search-quality MRR; all Ints, contentless), `action_run{name,kind,stepTypes,provider,clipKind,custom}`, `action_error{name,category}`, `transform_selection{captured}`, `copy_selection{length}` (detail-pane ⌘C — length only, never the text). Unit-tested. Wired through the app delegate: panel_open in `HistoryPanelController.show`; search/paste in `HistoryPanelViewModel` (search on a ~400ms debounce); action_run/action_error in `AppDelegate.runAction`; transform_selection in `handleTransformSelection`.
- `HistoryItem.swift` — `HistoryItem` (stored record; new fields stay **Optional** for backward-compatible synthesized `Codable` decode since the store reseeds on any decode failure — `imageDimensions`, `pinned`/`isPinned`, **`ocrText`**, **`sourceDeviceName`/`sourceDeviceType`**), `CapturedClip` (raw capture from the watcher), `ContentHash` (SHA-256 dedupe keys via CryptoKit). **`ocrText: String?`** is the Apple Vision OCR transcript for image clips — a **three-state sentinel**: `nil` = never OCRed (fresh clip / an OCR attempt that couldn't run — the backfill will pick it up), `""` = OCRed but no text found (backfill skips it, never loops), non-empty = recognized text. `searchableText` returns the inline text for text clips or the (non-empty) OCR transcript for image clips (the `""` sentinel + nil → nil); `FuzzyMatcher` + the VM deep-search pass use it so screenshots are findable by their contents. OCR text syncs as entity metadata even though image PNGs don't, so a screenshot synced from another device is searchable here. **`sourceDeviceName`/`sourceDeviceType: String?`** record which device captured the clip (a display name + `"mac"`/`"iphone"`) so the panel/list can show a small origin badge on a clip synced in from elsewhere — both optional/nil for pre-feature clips (no badge); every capture entry point on both platforms fills them in (see `CapturedClip`, `ClipboardWatcher`, `ClipListView.capture`). `CapturedClip` carries the same two fields (`forText` takes them too) so every capture site — the mac watcher, ⌃⇧V transform-selection, detail-pane copy-selection, iOS paste-capture — tags its origin the same way.
- `ClipOrigin.swift` — pure `ClipOrigin.originBadge(for:currentDeviceName:) -> OriginBadgeKind?`, shared by the mac panel row and the iOS list row: `nil` when the clip has no recorded device or its device name matches the current one, else `.mac`/`.iphone`/`.other` (an unrecognized `sourceDeviceType`) each with an SF Symbol (`laptopcomputer`/`iphone`/`questionmark.circle`). Unit-tested (`ClipOriginTests`).
- `SyncActivityMonitor.swift` / `SyncStatusLine.swift` (RecallyxCore) — **the single CloudKit sync observer for both platforms**, for "sync trust" visibility. `SyncActivityMonitor` (`@MainActor ObservableObject`) observes `NSPersistentCloudKitContainer.eventChangedNotification` and keeps `lastExportSuccess`/`lastImportSuccess: Date?`, `lastError: SyncActivityError?` (**category only** — a CKError code name or `<domain>#<code>`, NEVER `localizedDescription`, which can echo record content), `isActive` (event in flight), plus the iOS `isImporting`/`hasSyncedOnce` + `awaitNextImport(timeout:)` (parks on the shared `ImportWaiter`). Injectable notification center + `now` clock (mirrors `UsageJournal`'s seams). The state transition is the pure, value-type `SyncActivityState.reduced(kind:ended:succeeded:errorCategory:at:)` and the event kind is the constructable `CloudKitEventKind` enum, so the logic is hermetically testable without a real (non-constructable) `NSPersistentCloudKitContainer.Event`; `errorCategory(_:)` maps every `CKError.Code` (1...36, hardcoded — RecallyxCore doesn't import CloudKit) to its case name, e.g. `CKError.partialFailure`, falling back to `CKError.<n>` for an unrecognized code. The iOS `SyncStatusMonitor` (Sources/RecallyxiOS) is now a **thin wrapper** around one `SyncActivityMonitor` (`activity`), re-exposing `isImporting`/`hasSyncedOnce`/`awaitNextImport` and republishing its changes — one observer core, two consumers (mac Settings/menu-bar + iOS). **`SyncStatusLine.text(lastExport:lastImport:lastError:now:) -> String?`** is the pure formatter: `nil` (never synced, no error), `Last sync: ↑ 2 min ago` / `↓ 5 min ago` / both joined by ` · `, or `Sync error: <category> · <time>` when the error is the latest event (a newer success supersedes an older failure). Reuses `ClipTime.relative`. Unit-tested (`SyncStatusTests`).

The model is built **programmatically** (`ClipModel.makeModel()` — no `.xcdatamodeld`, stays CLT/SPM-buildable) as one entity `ClipEntity` mirroring `HistoryItem`, modeled CloudKit-compatible (every attr optional/defaulted, no unique constraints — dedupe stays app-level via `ContentHash`). Public API (`add`/`bump`/`delete`/`clear`/`setPinned`/`cap`/`imageURL`/`flush`/`onChange`/`items`, plus **`setOCRText(id:text:)`** + **`ocrBackfillCandidates()`** for OCR image search); the in-memory `items` array stays the canonical state (recency-ordered) and every mutation mirrors into Core Data via a debounced `persist`. **`setOCRText`** writes an image clip's OCR transcript (trims; empty→`""` sentinel; no-op on unchanged value or unknown id, so re-OCR from a dedupe-bump / racing tasks doesn't churn the dirty set); **`ocrBackfillCandidates()`** returns image clips with `ocrText == nil` whose PNG exists locally (the backfill work list). **`persist` is dirty-set–scoped (NOT a whole-array mirror):** each mutation marks its id in `dirtyIDs`/`deletedIDs`; `persist` upserts only the dirty ids and deletes only the deleted ids, never touching any other row. This is load-bearing for sync — the SQLite file is written concurrently by CloudKit imports, so a blind whole-array upsert would re-export stale fields and silently revert a remote pin/add/delete on a clip the app didn't touch. **Inserts vs mutations are distinguished (`addedIDs`, marked only in `add`/migration):** `persist` creates a new `ClipEntity` **only** for an id in `addedIDs`; a *mutation* (`bump`/`setPinned`/`setOCRText`/dedupe-bump) whose row is gone was **deleted on another device** (a CloudKit import removed it before the ~1s merge caught up), so `persist` **drops that write** (content-free `resurrection avoided` log) instead of recreating it — recreating would resurrect a clip the user deleted and re-export it fleet-wide (the OCR backfill's automatic `setOCRText` writes made this routine). The stale in-memory item is reconciled away by the next `mergeRemoteChanges` (fired by the same remote-delete notification). **Live remote merge:** the store observes `.NSPersistentStoreRemoteChange` (enabled by the store-description keys `NSPersistentHistoryTrackingKey` + `NSPersistentStoreRemoteChangeNotificationPostOptionKey` in `PersistenceController.makeStoreDescription` — history tracking is a safe, one-way opt-in; remote-change is inert with no sibling writer) and, debounced (~1s, injectable via `remoteMergeDelay`), runs `mergeRemoteChanges`: `flush()` pending local edits FIRST (dirty-set, so it can't clobber the import), then re-reads the store (`shouldRefreshRefetchedObjects` for fresh values) into `items` and fires `onChange` (content-free `+N -M` log). Panel keeps its snapshot-per-open behavior (no live mutation of an open panel); the iOS list, bound to `$items`, updates live. **Explicit sync-refresh (iOS pull-to-refresh + mac panel-open kick):** `NSPersistentCloudKitContainer` has **no public "fetch now" API** — the only public trigger is a **store reload** (`PersistenceController.reloadStore`: reset the viewContext so nothing is "in use", then remove + re-add the *same* store file, which re-runs setup+import; re-adding the same file keeps the mirroring metadata so it fetches only new changes, not a full re-download; the `.NSPersistentStoreRemoteChange` observer is on the coordinator, which survives the swap). `HistoryStore.refreshFromCloud(minInterval:now:)` flushes pending writes, then reloads — **no-op (returns false) when mirroring is inactive (sync off/unentitled) or throttled** (pure `HistoryStore.shouldRefresh` decides; mac passes **300s** so frequent ⌘⇧V opens don't thrash the store — each kick tears down + re-adds the CloudKit store on the main thread — iOS passes 0). `isCloudSyncActive` gates the UI; `refreshItemsFromStore()` re-reads after an awaited import. **Guarantee:** this is **best-effort, not a hard fetch** — the reload triggers an import, but whether new server rows arrive depends on CloudKit; iOS holds the spinner on `SyncStatusMonitor.awaitNextImport` (next completed `.import` or **~4s** timeout — the pull kick runs from the `ImportWaiter`'s `onParked` so it fires *after* the waiter is parked, closing the signal race; and since a caught-up device emits no `.import`, the short timeout is what ends the spinner), mac lands the rows on the next open via the merge. Real cross-device behavior is **attended-verification only** (needs the account + 2 devices). **Orphan reconciliation is skipped when `cloudSyncEnabled`** (as well as on the reseed/corrupt path and iOS's `reconcileImages: false`): a synced-in image entity's PNG never synced this phase, so reconciling would delete it and export that deletion cross-device. Merge/dirty-set/remote-delete/sync-skip-reconcile are unit-tested via a second `PersistenceController` on a real temp-file store (in-memory can't post remote-change). `items` stays pure recency order (pinned-first ordering is applied at the panel layer). Cap eviction (enforced on load too — `cap`'s `didSet` doesn't fire in `init`) **exempts pinned** (evicts oldest *unpinned* until within cap, leaving pins even above cap) and, like any other delete, **syncs its evictions fleet-wide** — a low cap on one device prunes every synced device down to it; this is **by design, documented in Settings/README, and deliberately left unguarded** (see #75) — orphan reconciliation (skipped on the reseed/corrupt-import path so backed-up PNGs survive). **Images stay on disk** as `images/<uuid>.png` (entity stores `imageFilename` only). **One-time JSON→Core Data migration:** on first launch when the store is empty and a legacy `history.json` exists → decode with the old logic, insert entities (ids/timestamps/pins preserved), then rename `history.json` → `history.json.bak`; idempotent (guarded by store-empty + the `.bak` rename), corrupt JSON tolerated (backed up to `.corrupt-*`, store stays empty). `init(…, inMemory:)` uses a `/dev/null` store for hermetic tests. ### Phase 2 — actions / AI
- `Action.swift` — `Action { name, icon, steps: [Step], output: OutputMode }`, `Step { type: .script|.ai, enabled, script, prompt, model? }` (generalizes AI Replace's `Preset`). **`OutputMode` (`.paste`/`.copy`/`.show`/`.append`, default `.paste`)** picks what happens to the result: paste it into the source app (today's behavior), copy to clipboard without pasting, show it in a panel result view, or append it silently to history. `Action` has a **custom `init(from:)`** so a pre-feature saved action (no `output` key) — and an unknown/future value — decodes to `.paste` (a synthesized decoder would reject the missing key); `encode` stays synthesized. **`ActionOutcome.plan(output:result:) -> ActionOutcome`** (`.skipEmpty`/`.paste`/`.copy`/`.show`/`.append`) is the pure, testable run-path decision (empty/whitespace result → `.skipEmpty` for every mode); `AppDelegate.runAction` switches on it and does the AppKit side-effects. Unit-tested (`ActionOutputTests`). `Action.defaults()` seeds the menu — AI text actions, a **dev script pack** (URL decode/encode, Base64 decode/encode, Decode JWT, Minify JSON — zero-config offline `python3` filters, placed after "Extract URLs" before the image actions), then image-friendly AI actions ("Extract text" / "Describe image"). `kindTag` → SCRIPT/AI. `Action.appendingMissingBuiltins(into:)` is the append-only, name-matched, idempotent merge behind the Actions-tab **"Restore built-in actions"** (↻) button — `AppSettings` only falls back to `defaults()` when the `actions` key is entirely absent, so this is how existing installs pick up newly shipped built-ins (and recover a default deleted by accident). Pure + unit-tested.
- `ActionInputs.swift` (RecallyxCore) — **run-time input placeholders.** A step's `script`/`prompt` can contain `{{INPUT}}` or `{{INPUT:Label}}`; running the action pauses to ask for each distinct label, then substitutes the value everywhere it appears. Pure + unit-tested: `placeholders(in: Action) -> [Placeholder]` (deduped by label across steps — one ask, substituted everywhere; bare/empty label → `"Input"`; labels may contain colons) and `apply(values:to:) -> Action` (transient copy, INPUT tokens replaced). Substitution runs **before** `{{TEXT}}` (`applyPromptTemplate`) — `apply` only touches INPUT tokens, leaving `{{TEXT}}` for the normal input-threading. Wired into the panel's `.inputPrompt` mode + the global-hotkey path; the entered value is **never logged** (reuses `action_run`, no new fields).
- `ActionRunner.swift` — `@MainActor`; threads text through enabled steps in order (`.script` → `ScriptRunner`, `.ai` → `AIClient` facade) via the shared `thread(_:current:)` loop. Two entry points share it: `run(_:on text:)` (text clips, unchanged) and `run(_:onImageData:)` (image clips — first enabled step must be `.ai`, gets the PNG → text, then remaining steps thread as text; `.script`-first throws `ActionError.scriptFirstOnImage`; empty pipeline → ""). The injected `runAI` seam is `(prompt, model?, input, imageData: Data?)`. Script/AI runners are **injectable** so tests are hermetic. A throwing step aborts before paste. **`ActionRunner.isEmptyResult(_:)`** (static, `nonisolated`, pure, unit-tested — `nonisolated` so `ActionOutcome.plan` can call it) reports whether a run produced nothing worth pasting (empty / whitespace-only); `AppDelegate.runAction` routes the result through `ActionOutcome.plan(output:result:)` and **skips output** on `.skipEmpty` for every mode (flashes "no output" + a "Action produced no output." notice, logs `action_error{category:emptyResult}`) — pasting "" would set the clipboard to "" and synth-⌘V over the user's current selection, silently wiping it. **The other outcomes branch by the action's `output` mode:** `.paste` = today's path (`ensurePasteTrusted` gate + synth-⌘V); `.copy` = set clipboard, **no** markSelfWrite (so the watcher captures the result as a fresh clip, like the paste path) + "Result copied" notice, no paste; `.show` = `historyPanel?.showResult(text)` (panel result view, no clipboard write until the user copies there); `.append` = `appendActionResult(text)` (`store.add` a text clip tagged `sourceAppName: "Recallyx"` + this device's `DeviceOrigin`, no clipboard/paste) + "added to history" notice. `action_run` logs the `output` rawValue (content-free). Transient runs (Custom…, edit-before-run) are built with the default `.paste`, so they keep paste semantics. `ActionError.missingApiKey(AIProvider)` names the right provider; `.imageNotSupported` means "needs a vision-capable model" (cloud always, + per-model Ollama vision; `.apple` text-only). Unit-tested.
- `AIProvider.swift` — **multi-provider routing** + two shared AI-step helpers all clients route through: **`AIClientDefaults.maxOutputTokens` (4096)** — the single output-token cap the cloud clients request (OpenAI `max_completion_tokens`, Anthropic `max_tokens`, Gemini `generationConfig.maxOutputTokens`; raised from the old hardcoded 1000 that silently truncated long OCR/summaries — clients also log when the response's finish/stop reason signals length truncation), and **`applyPromptTemplate(_:text:)`** — fills the AI prompt: substitutes `{{TEXT}}` when present, else **appends** the input on its own line so a prompt that forgot the placeholder still sees the clip (instead of silently dropping it). All five clients (OpenAI/Anthropic/Gemini/Ollama/Apple) use it; the Custom… path's `buildCustomPrompt` ensures `{{TEXT}}` upstream so it never double-appends. `AIProvider.provider(for:)` picks by model-id prefix (`apple:*` → `.apple`, `ollama:*` → `.ollama`, `gemini*` → `.gemini`, `claude*` → `.anthropic`, else `.openai`) — no schema migration, OpenAI stays default. `AIClient.complete(prompt:model:input:imageData:)` dispatches to `OpenAIClient`/`AnthropicClient`/`GeminiClient`/`OllamaClient`/`AppleClient`; cloud providers (OpenAI/Anthropic/Gemini) read a keychain key (`keychain` is `nil` for the local `.ollama`/`.apple` and the facade skips the key check), Ollama reads the configured base-URL closure. With `imageData` set it runs a vision request gated by the **model-aware** `AIProvider.supportsVision(forModel:)` (cloud → true, `.apple` → false, `.ollama` → per-model via `isOllamaVisionModel` — substring allowlist `["llava","vision","bakllava","moondream","minicpm-v"]` on the prefix-stripped lowercased name, so `ollama:llava`/`ollama:llama3.2-vision` pass but `ollama:llama3.2`/`qwen2.5`/`mistral` throw `ActionError.imageNotSupported`). The instance `supportsVision` flag stays provider-level (false for `.ollama`/`.apple`) but the gate uses the static model-aware check. Cloud providers (`.openai`/`.anthropic`/`.gemini`) report `supportsVision == true`. Add a provider here (case + keychain/dispatch + vision rule). Unit-tested.
- `OpenAIClient.swift` / `AnthropicClient.swift` / `GeminiClient.swift` / `OllamaClient.swift` — raw `URLSession` clients (chat-completions / Messages API `https://api.anthropic.com/v1/messages` / Gemini `generateContent` `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent?key=…` / local `\(baseURL)/api/generate`). **Gemini** is BYO-key (key as `?key=` query param), body `{"contents":[{"parts":[{"text": fullPrompt}]}]}`, vision appends an `inline_data` part (mime_type image/png, raw base64, no `data:` prefix), response text at `candidates[0].content.parts[0].text`; `GeminiError` mirrors `AnthropicError`. All three `complete` take an optional `imageData: Data?` (PNG bytes): non-nil → vision shape (OpenAI `image_url` data-URL; Anthropic `image` base64 source; **Ollama `"images": [<base64>]`** — raw standard base64, NO `data:` prefix); nil → the existing text shape. Ollama is **local, no auth, no key**, `stream:false`, 120s timeout, `ollama:` prefix stripped before send, friendly `notRunning`/`modelNotFound` (404) errors. **Ollama vision is per-model** (only multimodal locals like llava/llama3.2-vision; the facade gates non-vision models out). `ModelCatalog` (in `OpenAIClient.swift`) groups `.openAI`/`.anthropic`/`.gemini` (`gemini-3.5-flash`/`gemini-2.5-pro`/`gemini-3.1-flash-lite`)/`.ollama` (`ollama:llama3.2`/`qwen2.5`/`mistral` text + `ollama:llava`/`ollama:llama3.2-vision` vision)/`.apple` (`apple:on-device`); `.all = openAI + anthropic + gemini + ollama + apple`; `.default = gpt-4o-mini`. **Availability-aware pickers:** pure `ModelCatalog.groups(openAI:anthropic:gemini:ollama:apple:) -> [ModelGroup]` (flag-driven, fixed order OpenAI/Anthropic/Google Gemini/Ollama/Apple — unit-tested), `availableGroups()` computes the flags live (OpenAI/Anthropic/Gemini only when their keychain key is set, Apple only when `AppleClient.isAvailable`, Ollama **always** — local keyless v1 choice), and `groupsPreservingSelection(_:selected:)` appends a trailing single-item "Configured" group so a still-selected model from a now-unavailable provider doesn't blank the Picker. Both Settings model pickers route through these.
- `AppleClient.swift` — **on-device Apple Intelligence** via the FoundationModels system framework (macOS 26+), addressed `apple:*` (suffix ignored — the OS picks the model). **No key, no network, fully local; text-only in v1.** `complete` is `#if canImport(FoundationModels)`-guarded + runtime `#available(macOS 26, *)`-gated (app targets macOS 13+), with a throwing `#else`/unsupported-OS stub so it compiles on any SDK. Checks `SystemLanguageModel.default.availability` → friendly `AppleError.unavailable`/`unsupportedOS` when AI is off/undownloaded; runs via `LanguageModelSession().respond(to:).content`. `static var isAvailable` (macOS 26 + `availability == .available`; false where it can't import / OS < 26) gates the Apple group in the Settings model pickers. Unit-tested only via routing/guard (never calls the real model).
- `ScriptRunner.swift` / `KeychainStore.swift` / `Notifier.swift` — copied from AI Replace (env key `RECALLYX_SCRIPT`, keychain service `io.github.macrosak.recallyx`; accounts `openai-api-key` + `anthropic-api-key` + `gemini-api-key`).
- Action menu now shows built-ins → `Saved actions` divider → user actions (text clips only, with SCRIPT/AI tags). Running a saved action threads the clip text through `ActionRunner` and pastes the result (which re-enters history as a fresh top item — *not* marked self-copy). `AppSettings` extended with `defaultModel` + `actions` + `ollamaBaseURL` (default `http://localhost:11434`, `RECALLYX_OLLAMA_URL` env override; threaded to the facade via an `ActionRunner` closure like `defaultModel`) + **`providers: [ProviderConfig]`** (the explicit provider list — see below).

### Explicit providers + custom OpenAI-compatible endpoints
- `ProviderConfig.swift` (RecallyxCore) — `ProviderConfig { id, type: ProviderType, enabled, displayName, baseURL?, keychainAccount?, models? }` + `ProviderType` (`.openai/.anthropic/.gemini/.ollama/.apple/.openAICompatible`). The user's explicit provider list, surfaced in the **Providers** Settings tab; an *enabled* entry makes that provider's models appear in the pickers (replaces the old keychain-presence/always-on heuristic). **Holds only references — secrets stay in the Keychain** (`keychainAccount`; custom providers use a per-id account `custom-<uuid>-api-key`). **Migration:** `AppSettings.providers` defaults via `ProviderConfig.seedFromCurrentReality(...)` when the settings key is absent — cloud providers whose keychain key exists, Apple if `AppleClient.isAvailable`, Ollama always, no custom; a present (or explicitly empty `[]`) list decodes unchanged. Pure + unit-tested.
- **Custom-endpoint routing:** a custom provider's models are addressed **`custom:<providerID-uuid>:<model>`**. `AIProvider.provider(for:)` maps a `custom:` prefix → `.openAICompatible`; `AIProvider.parseCustomModel(_:)` splits id/model (first two `:` only, so `org/model:tag` survives). The `AIClient` facade + `ActionRunner` take a `customEndpoint: (providerID) -> (baseURL, keychainAccount)?` resolver (alongside `ollamaBaseURL`); on a `custom:*` id it resolves the endpoint, strips the prefix, reads the key from the Keychain by account, and calls **`OpenAIClient` with a configurable `baseURL`** (default = OpenAI; `OpenAIClient.chatCompletionsURL(baseURL:)` appends `/chat/completions` unless already present). Custom models are treated as **vision-capable** (`supportsVision == true`) — OpenAI-compatible servers vary, so we let the server reject rather than pre-block. `ActionError.customEndpointUnavailable` when a `custom:` step's provider was removed/disabled. The production resolver lives in `RecallyxApp` (looks up the enabled provider by id in `settings.providers`).
- **Availability:** `ModelCatalog.groups(forProviders: [ProviderConfig])` (pure, order-preserving) builds the picker groups from the *enabled* entries in list order (drag-reorder = picker order); each custom provider becomes its own group listing `custom:<id>:<model>` ids (blank model lists skipped). `availableGroups(for:)` forwards the live list. Both Settings pickers + the Actions step picker read this one source (`StepCard` takes the groups). `groupsPreservingSelection` unchanged. The old flag-driven `groups(openAI:anthropic:gemini:ollama:apple:)` remains for its pure tests but no longer drives availability.
- `SettingsProvidersView.swift` — the Providers tab, master/detail mirroring the Actions tab. **Left = a native sidebar `List(selection:)`** (`.listStyle(.sidebar)` — Finder-style selection + whole-row `.onMove` drag-reorder; row content is icon + name **only**, no custom highlight pill / inline toggle, so the whole row drags — the #50 lesson). Structural edits (`add`/`delete`/`.onMove`) `flush()` immediately. Pure `neighborSelection` unit-tested.

Apple/Ollama, only configured cloud ones) after the leading "Use default" — same availability + selection-preserving logic as the Default-model picker. - **Ad-hoc AI in the panel.** The vm gains `.custom` and `.edit` modes. The action menu's **Custom…** entry (text clips) opens a one-off prompt column → ↵ runs a transient single-`ai`-step action. **Edit-before-run**: ⇥ on a highlighted saved action enters `.edit`, showing step 1's body editable; ⇥ paginates steps; ⌘↵ runs the modified *transient copy* (the saved action is untouched). Both go through the same `onRunAction` → `ActionRunner`. `CustomPromptColumn`/`EditStepsColumn` match the design. Focus moves to the editor in custom/edit modes, to the search field in list/actions.
- **Result view (`.result` mode).** The `show` output mode's presentation: after the async run completes `AppDelegate.runAction` calls `HistoryPanelController.showResult(text)` → `show(resultText:)` builds a fresh panel + VM and calls `vm.enterResult(text)` (`mode = .result`, `resultText` set). `HistoryPanelView` renders a dedicated full-panel view for `.result` (bypassing the list/isEmpty chrome): a `ResultHeader` ("Result") + `ResultColumn` — a read-only selectable `LargeTextView` (native ⌘C / ⌘A) plus a Copy-all button that `Paster.setClipboardText`s the whole result **unmarked** (so it enters history). Esc closes (controller's `handleKeyDown` `.result` case: esc → `vm.cancel()` → `onDismiss`; everything else flows to the text view). `panel_open` logs `mode: actionResult`. VM state (`enterResult`/esc-dismiss) unit-tested.
- **Run-time input prompts (`.inputPrompt` mode).** Every run path (action-menu ↵, ⌘1–9 quick-run, edit-mode ⌘↵, Custom…) routes through the vm's private `launch(_:on:)`: an action with `{{INPUT:Label}}` placeholders (via `ActionInputs.placeholders`) enters `.inputPrompt` instead of running — one column (`InputPromptColumn`) per distinct label, ↵ advances / (on the last) substitutes via `ActionInputs.apply` and runs the transient copy, esc backs out to the action menu; a blank value is a no-op (like Custom…'s guard). No placeholders → runs immediately (unchanged). The controller's `handleKeyDown` treats `.inputPrompt` like `.custom` (↵ confirm, esc back, ⇥ swallowed, typing → the field, focused as `.editor`). **Global-hotkey path:** a per-action hotkey bound to an action WITH placeholders can't supply the value, so `AppDelegate.handleActionHotkey` opens the panel on that action's input prompt (`HistoryPanelController.showInputPrompt` → `vm.openInputPrompt(for:focusId:)`) rather than running silently with the raw token — same "open on the captured clip by id" idea as ⌃⇧V's `showOnTopActions`. Settings → Actions shows a caption under the step body: "Use {{INPUT:Label}} to ask for a value when the action runs." Unit-tested (VM flow + `ActionInputsTests`).
- **The search field retargets by mode.** List mode filters clips ("Search clipboard…" / "N clips"); entering any action state clears it and switches to "Search actions…" / "N actions", filtering the menu (`filteredMenuItems`, order-preserving so the Saved-actions divider still groups). The clip query is stashed on ⇥ and restored on esc; `query`'s `didSet` routes to the active domain via `onQueryChanged`.

- `AccessibilityClient.swift` — trimmed copy of AI Replace's (read-only: selection capture + one-prompt-per-session permission flow; no write-back, since results paste via synth ⌘V). **`ensureTrustedOrPrompt()` (the single gate every untrusted paste/⌃⇧V/action-hotkey path routes through) calls `AXIsProcessTrustedWithOptions([kAXTrustedCheckOptionPrompt: true])` on the untrusted path** — this both pops the real macOS system permission dialog AND **re-registers the app's row in System Settings → Accessibility** (after a `tccutil reset` the row is gone; a plain `AXIsProcessTrusted()` never brings it back, so the old code left the user with nothing to enable). The system prompt is gated once per session (`systemPromptRequestedThisSession`; macOS ignores in-process repeats anyway), and the custom NSAlert (deep-links Settings, explains the enable-then-relaunch requirement) still shows once per session right after. `captureSelection` reads `kAXSelectedText`; `captureSelectionViaCopy(markSelfWrite:)` is the Chromium/Gmail fallback — synth ⌘C, poll the pasteboard `changeCount` (~500ms), no bump ⇒ no selection. **It snapshots the user's clipboard first (`PasteboardSnapshot`, non-lossy: every type on every item) and RESTORES it after reading the copied selection**, then calls the injected `markSelfWrite` (wired to `watcher.markSelfWrite`) so the watcher's next tick treats the restore as our own write and won't recapture/bump it — without this, ⌃⇧V on a Chrome/Gmail selection permanently clobbered whatever the user had copied. The selection still reaches history via `handleTransformSelection`'s `store.add`, so restoring the live pasteboard is correct. `PasteboardSnapshot.capture/restore` is a small value type, unit-tested via a private named `NSPasteboard` (the synth-⌘C timing around it stays AppKit-bound). `handleTransformSelection` tries AX then the fallback, `store.add`s the clip to the top and **keeps the returned id**, then `historyPanel.showOnTopActions(focusing: id)` opens the panel already on that clip's action menu. **Targets the clip by id** (`HistoryPanelViewModel.openActionsOnTop(focusId:)`, falls back to `filtered[0]`) — the panel sorts pinned-first, so opening on `selectedIndex = 0` would land on the first pinned clip, not the captured selection.

## Lessons carried over from AI Replace — don't relitigate
- **MenuBarExtra content is lazy.** Use `NSApplicationDelegate.applicationDidFinishLaunching` for launch wiring, never the content's `.task`.
- **Ad-hoc signing invalidates TCC every rebuild.** Stable identity via `scripts/create-signing-identity.sh` → grant survives rebuilds.
- **TCC stale entries survive System Settings toggles.** Fix: `tccutil reset Accessibility io.github.macrosak.recallyx`.
- **After `tccutil reset` the Settings row disappears; only `AXIsProcessTrustedWithOptions(prompt)` re-registers it.** A plain `AXIsProcessTrusted()` check never re-adds the row, so the user opens System Settings → Accessibility and finds nothing to enable. The app now fires the prompted-options call on the first untrusted attempt (in `ensureTrustedOrPrompt`), which both pops the system dialog and restores the row.
- **`open` doesn't relaunch a running app** — it foregrounds. `install.sh` does `killall` first.
- **Carbon `RegisterEventHotKey`** returns `eventHotKeyExistsErr=-9878` if the combo is taken globally.
- **Chromium/Electron silently drop `kAXSelectedText` writes** — re-read to verify, fall back to synthesized ⌘V at `.cghidEventTap`. (Phase 2 paste path.)
- **Chromium/Gmail don't expose `kAXSelectedText` reads either** (error or empty even with a selection) — fall back to synthesized ⌘C + pasteboard `changeCount` polling. AI Replace dodged this with a separate manual-copy hotkey (⌘⌥V); Recallyx synthesizes the copy itself.
- **OpenSSL 3 PBES2 p12 is rejected by macOS Security** — `create-signing-identity.sh` uses `/usr/bin/openssl` (LibreSSL).
- **SwiftUI `.buttonStyle(.plain)` icon buttons only hit-test the glyph's opaque pixels** — add `.contentShape(Rectangle())` so the whole frame is clickable (a thin +/−/↻ glyph otherwise drops most clicks; caused the action-delete "can't click minus" bug).

## When the user reports a problem
1. App-side log: **`~/Library/Logs/Recallyx/recallyx.log`** (+ rotated `.1`) is now persisted on disk by default (`FileLog`) — content-free, so a past bug is already captured. If logging was disabled, fall back to the `log stream` predicate above (info-level os_log is **not** persisted to disk — `log show` won't have it; use live `log stream`, or run the binary directly for the stderr mirror).
2. TCC log (⌃⇧V permission): `log show --predicate 'subsystem == "com.apple.TCC" AND eventMessage CONTAINS "recallyx"' --last 5m --info --style compact`. `Failed to match existing code requirement` ⇒ stale TCC entry — `tccutil reset Accessibility io.github.macrosak.recallyx`.
3. Codesign state: `codesign -dvvv Recallyx.app 2>&1 | grep -E "Authority|Signature"`. `Authority=Recallyx Dev` good; `Signature=adhoc` ⇒ TCC re-grant pain.
4. Re-bundle before testing hotkeys/UI: `swift build` updates `.build/`, but the `.app` binary is only refreshed by `scripts/bundle.sh`. Running a stale `.app` is a classic "my change didn't take" trap.

## Don't
- Add Xcode-only deps (no `#Preview` macros — Command Line Tools only).
- Move launch wiring onto MenuBarExtra content's `.task`.
- Run `tccutil reset` or `security add-trusted-cert` without explicit user confirmation.
- Test a code change against a stale `.app` — re-run `bundle.sh` first.
